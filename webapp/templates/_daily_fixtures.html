The 7 radios/labels/content-divs below are all deliberately flat, direct siblings of one parent — Tailwind's peer-checked relies on a plain CSS sibling combinator, which only matches actual siblings, not elements nested inside an earlier sibling. Nesting the radios inside a wrapper div (e.g. for a flex tab-bar) would silently break every peer-checked reference below it. Each content div only ever tests its OWN day's peer — unlike a 2-way toggle there's no single "else" peer to hide behind, so every div is `hidden` by default and opts into `peer-checked/{day}:block` for exactly one day. Every peer/{day} and peer-checked/{day}:* class name below is written out literally, one block per day, NOT built by interpolating a Jinja loop variable into the class string — Tailwind generates its CSS by statically scanning template *source* for complete, literal class-name tokens, before Jinja ever runs, so a class name built at render time never matches anything in that scan and silently compiles to no CSS at all.
